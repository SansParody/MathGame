# 1. Введение

### 1.1. Обзор: цель спецификации

Целью данной спецификации является определение требований к программному продукту «Обучающая игра по высшей математике». Документ устанавливает основные возможности приложения, особенности его функционирования, требования к пользовательскому интерфейсу и качеству работы.

Спецификация предназначена для определения задач разработки, организации процесса проектирования и проверки соответствия готового продукта установленным требованиям.

### 1.2. Объём проекта

Проект предполагает разработку интерактивной обучающей игры для студентов технических вузов, изучающих высшую математику. Приложение должно предоставлять возможность выполнять математические задания в игровой форме, получать обратную связь и отслеживать результаты.

В рамках проекта планируется реализовать:
- главное меню и систему навигации;
- выбор учебных тем;
- выбор уровней сложности;
- систему математических заданий;
- автоматическую проверку ответов;
- начисление игровых баллов;
- отображение результатов и прогресса пользователя.

Разработка направлена на создание дополнительного инструмента для самостоятельного изучения и закрепления материала по высшей математике.

### 1.5. Обзор продукта

Обучающая игра по высшей математике представляет собой интерактивное приложение, предназначенное для самостоятельной подготовки студентов.

Основной принцип работы заключается в последовательном выполнении математических заданий. Пользователь выбирает тему и уровень сложности, решает предложенные задачи и получает оценку своих ответов.

Приложение должно сочетать образовательную составляющую с игровыми элементами, такими как начисление баллов, прохождение уровней и отслеживание результатов. Это позволит сделать процесс самостоятельного обучения более интерактивным и поддерживать заинтересованность пользователей.

# 2. Общее описание

### 2.1. Системная среда

Разработка программного продукта осуществляется с использованием следующих инструментов и технологий:

- **Unity** — основная среда разработки, предназначенная для создания игровой логики и пользовательского интерфейса;
- **C#** — язык программирования для реализации игровых механик, проверки ответов и обработки действий пользователя;
- **Figma** — дополнительный инструмент для предварительного проектирования экранов и визуальных элементов интерфейса.

Приложение предполагается использовать на персональных компьютерах. Конкретная операционная система и требования к аппаратному обеспечению определяются при подготовке итоговой сборки.

Для реализации основных функций не требуется обязательное подключение к сети Интернет, если учебные материалы и задания хранятся непосредственно в приложении.

### 2.2. Спецификация функциональных требований

Программный продукт должен включать следующие основные компоненты:

**1. Главное меню.**

Предоставляет пользователю доступ к основным разделам приложения. Содержит название игры, кнопку начала игры, переход к результатам, настройки и выход из приложения.

**2. Раздел выбора тем.**

Предназначен для выбора направления изучения высшей математики. Темы могут включать математический анализ, линейную алгебру, аналитическую геометрию и другие разделы в зависимости от учебного содержания проекта.

**3. Раздел выбора сложности.**

Предоставляет возможность выбрать уровень подготовки. Задания должны различаться по сложности и постепенно усложняться по мере прохождения игры.

**4. Игровой раздел.**

Содержит математические задания, варианты ответа или поле для его ввода, кнопку подтверждения и информацию о текущем прогрессе.

**5. Система проверки ответов.**

Обеспечивает автоматическое определение правильности решения. После отправки ответа пользователь получает уведомление о результате и, при необходимости, правильный ответ или пояснение.

**6. Система начисления баллов.**

Отвечает за подсчёт результатов выполнения заданий. За правильные ответы пользователю начисляются баллы в соответствии с установленными правилами.

**7. Раздел результатов.**

Отображает итог прохождения выбранного уровня, количество набранных баллов, правильных и неправильных ответов.

**8. Система прогресса.**

Предназначена для отображения пройденных уровней и достигнутых результатов. Позволяет пользователю оценивать собственные успехи в процессе обучения.

# 3. Технические требования

### 3.1. Требования к интерфейсу

Пользовательский интерфейс должен иметь понятную структуру, единое визуальное оформление и обеспечивать удобство взаимодействия с приложением.

Предполагается наличие следующих экранов:

- **Главное меню** — название игры и основные элементы навигации.
- **Выбор темы** — список доступных разделов высшей математики.
- **Выбор уровня** — перечень уровней сложности.
- **Игровой экран** — условие задания, поле ввода или варианты ответа, кнопка подтверждения.
- **Экран обратной связи** — информация о правильности ответа.
- **Экран результатов** — количество набранных баллов и статистика прохождения.
- **Экран прогресса** — сведения о пройденных уровнях и достижениях.

Дополнительно устанавливаются следующие требования:
- текст должен быть хорошо читаемым;
- математические формулы и обозначения должны отображаться корректно;
- кнопки и другие элементы управления должны иметь понятные названия;
- цветовое оформление должно обеспечивать достаточную контрастность;
- расположение элементов должно быть единообразным на всех экранах.

### 3.2. Функциональные требования

Функциональные требования определяют поведение приложения со стороны пользователя.

**FR-01. Запуск приложения.** Система должна обеспечивать запуск игры и отображение главного меню.

**FR-02. Навигация.** Пользователь должен иметь возможность переходить между основными разделами приложения и возвращаться в главное меню.

**FR-03. Выбор темы.** Система должна предоставлять пользователю возможность выбрать доступный раздел высшей математики.

**FR-04. Выбор сложности.** Система должна предоставлять возможность выбора доступного уровня сложности.

**FR-05. Отображение заданий.** После выбора темы и уровня система должна отображать соответствующие математические задания.

**FR-06. Ввод ответа.** Пользователь должен иметь возможность вводить ответ или выбирать один из предложенных вариантов.

**FR-07. Проверка ответа.** После подтверждения ответа система должна автоматически определять его правильность.

**FR-08. Обратная связь.** Система должна отображать сообщение о результате выполнения задания.

**FR-09. Начисление баллов.** За правильное выполнение задания система должна начислять пользователю баллы.

**FR-10. Подсчёт результатов.** Система должна учитывать количество правильных и неправильных ответов и формировать итоговый результат.

**FR-11. Завершение уровня.** После выполнения всех заданий система должна отображать итоговый экран.

**FR-12. Повторное прохождение.** Пользователь должен иметь возможность повторно пройти завершённый уровень.

**FR-13. Отслеживание прогресса.** Система должна отображать информацию о результатах прохождения и достигнутых уровнях.

**FR-14. Обработка некорректных данных.** Система должна информировать пользователя о необходимости исправить пустой или некорректно заполненный ответ.

### 3.3. Нефункциональные требования

Нефункциональные требования устанавливают характеристики качества и условия работы программного продукта.

**1. Удобство использования**
- интерфейс должен быть интуитивно понятным;
- основные функции должны быть доступны через главное меню;
- навигация не должна вызывать затруднений;
- сообщения системы должны быть понятными пользователю.

**2. Надёжность**
- приложение должно корректно обрабатывать действия пользователя;
- ошибки при вводе ответов не должны приводить к завершению игры;
- проверка заданий и начисление баллов должны выполняться корректно;
- приложение должно сохранять стабильность при стандартных сценариях использования.

**3. Производительность**
- запуск и работа приложения не должны сопровождаться существенными задержками;
- переходы между экранами должны выполняться плавно;
- математические задания должны отображаться без нарушения структуры интерфейса.

**4. Совместимость**
- приложение должно корректно работать на выбранной целевой платформе;
- все используемые компоненты должны быть совместимы с выбранной версией Unity;
- интерфейс должен корректно отображаться при предусмотренных разрешениях экрана.

**5. Сопровождаемость**
- программный код должен иметь логичную структуру;
- основные функции должны быть разделены на отдельные компоненты;
- добавление новых заданий и учебных тем должно быть возможным без существенной переработки приложения.

**6. Безопасность и сохранность данных**
- приложение не должно допускать повреждения локальных данных пользователя;
- вводимые пользователем значения должны проходить проверку;
- при реализации сохранения прогресса должна предусматриваться возможность корректного восстановления результатов.

---

**Итог:** разработанный программный продукт должен представлять собой работоспособную обучающую игру, позволяющую студентам изучать и закреплять материал по высшей математике посредством интерактивных заданий, автоматической проверки ответов и игровых механик.
