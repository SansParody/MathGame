# 1. Введение

### 1.1. Обзор: цель спецификации

Цель cпецификации - определение требований к программному продукту. Документ устанавливает основные возможности приложения, особенности его функционирования, требования к пользовательскому интерфейсу и качеству работы.

### 1.2. Объём проекта

Проект предполагает разработку интерактивной обучающей игры для студентов технических вузов, изучающих высшую математику. Приложение должно давать возможность выполнять математические задания в игровой форме, получать обратную связь и отслеживать результаты. Разработка направлена на создание дополнительного инструмента для самостоятельного изучения и закрепления материала по высшей математике.

# 2. Общее описание

### 2.1. Системная среда

Разработка программного продукта осуществляется с использованием следующих инструментов и технологий:
- Unity - основная среда разработки;
- C# - язык программирования для реализации игровых механик;
- Figma - дополнительный инструмент для прототипирования интерфейса;
- Krita - дополнительный инструмент для рисования визуальных элементов.
Приложение предполагается использовать на ОС Windows. Для реализации основных функций не требуется обязательное подключение к сети Интернет.

### 2.2. Спецификация функциональных требований

Предполагаются следующие элементы:
- Главное меню: Предоставляет пользователю доступ к основным разделам приложения. Содержит название игры, кнопку начала игры, переход к результатам, настройки и выход из приложения
- Раздел выбора тем: Предназначен для выбора направления изучения высшей математики. Темы могут включать математический анализ, линейную алгебру, аналитическую геометрию и другие разделы в зависимости от учебного содержания проекта.
- Раздел выбора сложности: Предоставляет возможность выбрать уровень подготовки. Задания должны различаться по сложности и постепенно усложняться по мере прохождения игры.
- Игровой раздел: Содержит математические задания, варианты ответа или поле для его ввода, кнопку подтверждения и информацию о текущем прогрессе.
- Система проверки ответов: Обеспечивает автоматическое определение правильности решения. После отправки ответа пользователь получает уведомление о результате и, при необходимости, правильный ответ или пояснение неправильного.
- Раздел результатов: Отображает итог прохождения выбранного уровня, количество правильных и неправильных ответов
- Система прогресса: Предназначена для отображения пройденных уровней и достигнутых результатов. Позволяет пользователю оценивать собственные успехи в процессе обучения.

# 3. Технические требования

### 3.1. Требования к интерфейсу
Устанавливаются следующие требования:
- Наличие следующих экранов и их содержания:
  - Главное меню: название игры и основные элементы навигации.
  - Выбор уровня: перечень доступных уровней и уровней сложности.
  - Игровой экран: условие задания, поле ввода или варианты ответа, кнопка подтверждения.
  - Экран обратной связи: информация о правильности ответа.
  - Экран результатов: статистика прохождения.
  - Экран прогресса: сведения о пройденных уровнях и достижениях.
- Текст должен быть хорошо читаемым.
- Математические формулы и обозначения должны отображаться корректно.
- Кнопки и другие элементы управления должны иметь понятные названия.
- При наведении на интерактивные элементы появляются всплывающие подсказки.
- Цветовое оформление должно обеспечивать достаточную контрастность
- Расположение элементов должно быть единообразным на всех экранах
- Поддерживается адаптивная вёрстка для экранов с разным разрешением

### 3.2. Функциональные требования

Функциональные требования определяют поведение приложения со стороны пользователя.

- Система должна обеспечивать запуск игры и отображение главного меню
- Пользователь должен иметь возможность переходить между основными разделами приложения и возвращаться в главное меню.
- Система должна предоставлять пользователю возможность выбрать доступный раздел высшей математики.
- Система должна блокировать уровень до завершения предыдущих.
- Система должна предоставлять возможность выбора доступного уровня сложности.
- После выбора темы и уровня система должна отображать соответствующие математические задания.
- Система должна сама генерировать задания по теме.
- Пользователь должен иметь возможность вводить ответ или выбирать один из предложенных вариантов.
- После подтверждения ответа система должна автоматически определять его правильность
- Система должна отображать сообщение о результате выполнения задания.
- Система должна учитывать количество правильных и неправильных ответов и формировать итоговый результат.
- После выполнения всех заданий система должна отображать итоговый экран.
- Пользователь должен иметь возможность повторно пройти завершённый уровень.
- Система должна отображать информацию о результатах прохождения и достигнутых уровнях.

### 3.3. Нефункциональные требования

1. Надёжность
- Приложение должно корректно обрабатывать действия пользователя
- Ошибки при вводе ответов не должны приводить к завершению игры
- Проверка заданий и начисление баллов должны выполняться корректно
- Приложение должно сохранять стабильность при стандартных сценариях использования

2. Производительность
- Запуск и работа приложения не должны сопровождаться существенными задержками
- Частота кадров не менее 60 FPS

3. Совместимость
- Приложение должно корректно работать на выбранной целевой платформе
- Интерфейс должен корректно отображаться при предусмотренных разрешениях экрана

4. Сопровождаемость
- Программный код должен иметь логичную структуру и сопровождаться комментариями
- Основные функции должны быть разделены на отдельные компоненты
- Добавление новых заданий и учебных тем должно быть возможным без существенной переработки приложения

5. Безопасность
- Приложение не должно допускать повреждения локальных данных пользователя
- При реализации сохранения прогресса должна предусматриваться возможность корректного восстановления результатов
